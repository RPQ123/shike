招生计划人数

当前场景的依据

高一580人、高二530人、高三500人，共1610人，按2026、2025、2024年官方招生计划设置。 16个窗口、480个座位和放行时刻用于实验比较，可在设置中修改。

班级按每组约50人划分；布局按学生描述绘制。人数依据招生计划，其他设置可按实际情况调整。

计算方法与指标

模型按事件发生顺序计算：班级放行 → 步行到达 → 预计取餐完成最早的窗口排队 → 取餐 → 等座用餐 → 返程。

完整用时 = 放行延后 + 集合步行 + 排队 + 取餐 + 等座 + 用餐 + 返程

完整用时从各年级最早允许放行起算，按时完成以配置的返程截止时刻判断。P95 排队为 95% 分位；年级差为各年级平均完整用时的最大值减最小值，不能单独代表公平。

每轮 A / B 使用相同种子生成随机需求。差值为 B − A；95% 区间描述模型内随机波动，不包含输入参数不准确的误差。

布局依据项目交流采用两侧窗口、中间座位、前后进出；具体尺寸与两端人流比例为示意。3D 与 2D 回放同一份计算记录。人物抽样显示，人数指标按全量记录统计；示意面积不能用于计算现实密度。

三个学生，一个窗口

三人同时到达，每人取餐 10 秒。开始服务分别在第 0、10、20 秒；排队分别为 0、10、20 秒。

平均排队 = (0 + 10 + 20) ÷ 3 = 10 秒

如果三人改为第 0、10、20 秒依次到达，每人的现场排队都为零；但从共同允许时刻算起，完成取餐仍在第 10、20、30 秒。为什么排队少了，却没有更早完成？

例子的适用范围

此处忽略步行与用餐，可用配套 Python 教学模型验证；主仿真还包含通用窗口、座位与返程。

研究自查：五个问题
  1. 为什么要同时看排队时间和完整用时？
  2. 同一随机种子怎样让两种方案的比较更公平？
  3. 某年级等待变少，是否可能让另一年级更晚完成？
  4. 如果食堂统一送餐，当前模型哪里不再适用？
  5. 哪些工作是你亲自完成的，哪些由教师、参考项目或 AI 协助？
